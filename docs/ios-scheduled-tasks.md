# iOS 定时任务

本次实现采用方案最后收敛的首版范围：沿用 `ScheduledTask`、固定时间/重复规则和原有三种执行模式，增加提前准备结果的执行策略。没有新的“主动消息”入口或闲置触发日程。

- Android、桌面继续到期执行。iOS 前台到期可执行原有任务；后台依靠已经登记的本地通知。
- iOS 新任务默认允许提前准备；已有任务默认不允许。`regenerate` 仅在到期时执行。
- 准备只调用文字模型，读取当前助手、会话选中版本、截断边界、有效摘要、记忆、指令和世界书。历史最多 64 条、正文最多 32000 个 UTF-16 单元。不读取附件、不运行工具、不使用自定义请求体；不能代替需要实时信息或外部操作的任务。
- 准备过程不创建聊天、不追加消息、不推进世界书状态或日程。输出存于独立的设备本地结果区，不进入聊天上下文/摘要/记忆。
- 每次只准备下一次计划执行。新任务默认提前窗口 24 小时，可选 30 分钟、1/2/4/6/8/12/18/24 小时，已有任务使用保存的时长。例如第二天 08:00 的任务，前一天中午打开 App 时即可准备。最多尝试 2 次、冷却 10 分钟；全局一次只准备一个，每小时最多 6 次。失败、取消、废弃均计入尝试次数，自动 HTTP 重试关闭。
- 创建/修改任务、启动、进入准备窗口、前台安静 45 秒、切换到后台提供准备机会；聊天变化仅做失效检查。最近到期的任务优先。
- 严格上下文模式下，新消息、编辑旧消息、消息版本/截断/助手配置变化使结果失效。快照模式允许后续聊天变化，但删除目标或修改任务仍会失效。准备中的晚到结果也需通过版本检查。
- `taskId + scheduleRevision + scheduledFor` 确定一次计划执行。准备与重试共用运行记录；暂停后重新启用保留此次预算。手动“立即执行”使用独立运行记录。
- 到期前先登记提醒（或跳过），生成成功后用同一通知 ID 替换成结果。通知未授权/队列已满时显示“未登记”，不声称已送达。iOS 前台抑制兜底提醒，防止提醒后又发执行结果。
- 到期结果在 App 有机会运行时，通过 SQLite 事务幂等追加任务指令和原始回复。发布意图先持久化，固定消息 ID 保证崩溃恢复不重复写入。启动、恢复前台和发送新消息之前先对账。通知点击定位到对应结果。
- 改动结果预览/全局隐私设置会重登记通知；不会通过修改 UI 开关继续暴露原来的待发正文。已经展示的系统通知不作可撤回保证。
- 任务/准备结果/预算均为设备本地数据，排除在可迁移备份之外。沿用桌面存储键，保留原来已存在的任务。

## 系统边界

本地通知登记、取消和短期后台执行由 `ScheduledTaskNotifications.swift` 适配；调度和运行记录仍归统一服务。后台时间到期会取消本次请求。系统可能暂停/结束进程，因此仅提前准备有机会成功，不能保证任意时间在后台调用模型。

相关平台文档：[本地通知](https://developer.apple.com/documentation/usernotifications/scheduling-a-notification-locally-from-your-app)、[短期后台执行](https://developer.apple.com/documentation/uikit/extending-your-app-s-background-execution-time)。

系统时区变化会在下一次运行机会撤销未来候选并重新计算本地日程。App 未运行期间已登记的通知仍使用登记时的具体时刻。跨时区旅行时应打开 Kelivo 重新核对。

首版没有 App Intents、快捷指令执行入口或远端执行器。这些是原方案列出的后续增强入口，不能用本地预生成冒充后台实时执行。几天不打开 App 也不会无限补生成过去的任务。

## 待人工真机验收

使用测试服务商/会话，创建未来几分钟执行的一次性任务，检查：

1. 通知授权允许/拒绝；提前结果只出现在任务状态，未到期聊天不变。
2. 准备过程中立即退到后台、锁屏、强制退出；成功结果或预先登记的提醒符合状态，半成品不进入聊天。
3. 反复切换 App、修改任务、暂停/重新启用、删除任务/会话、编辑旧消息/切换版本；没有旧通知和无界重试。
4. 到期时另一条回复仍在生成；通知点击、直接打开 App、再次重启；结果正文一致，只追加一次。
5. 关闭预览或打开全局隐私模式后，系统待发通知已更新；重新允许预览后，通知正文与聊天结果一致。
6. 连续数日不打开、重启手机、关闭后台刷新、跨时区/夏令时；不补执行一串过期模型请求。

单元测试和模拟器构建不能证明锁屏、系统回收、强制退出等真机交付行为。
